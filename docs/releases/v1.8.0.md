# Release v1.8.0

`v1.8.0` improves OpenCode v2 model discovery with a user-facing manual refresh command and a shared, serialized refresh flow for startup, configuration changes, agent tools, and command execution.

## Added

### Manual V2 Refresh Command

The OpenCode v2 adapter now registers the following Server Command:

```text
/models-discovery-refresh
```

The command refreshes models from the current provider configuration and reports the result in the active session. It uses the same refresh operation as the existing `models_discovery_refresh` agent tool.

### Refresh Feedback

Refresh results now use a consistent format:

```text
Model discovery refreshed: discovered 12 models from 2 providers.
```

Failures return a safe user-facing message without exposing credentials or authorization details.

## Changed

### Unified V2 Refresh Flow

V2 refresh operations now:

- reload the current OpenCode provider registry before discovery;
- rebuild provider configuration and discovery options from the current registry;
- serialize startup retries, configuration updates, agent-tool refreshes, and manual command refreshes through one operation queue;
- keep integration and provider transforms registered once during plugin setup;
- preserve full inventory replacement semantics after each discovery attempt.

This makes manual refresh and `config.updated` use the same path and ensures changes to provider endpoints, filters, enablement, or credentials are reflected consistently.

### V2 Documentation

The V2 documentation now describes the manual refresh command, its relationship to the existing agent tools, and the current session-based feedback behavior.

### Development and Security Tooling

This release also includes routine updates to development dependencies and the plugin security scanner action.

### Removed Legacy Combined E2E Test

The old combined V1/V2 end-to-end test was removed because it depended on machine-specific OpenCode paths and a live provider endpoint. The regular unit/integration test suite and the local provider probe remain available for validation.

## Compatibility

- Existing OpenCode v1 configurations remain supported.
- Existing OpenAI-compatible and Anthropic-compatible V2 discovery behavior remains supported.
- OpenCode v2 discovery remains beta and requires a V2 host with the V2 plugin API.
- The V2 manual refresh command does not modify `opencode.json` or manage credentials.
