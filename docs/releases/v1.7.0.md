# Release v1.7.0

`v1.7.0` adds OpenCode v2 discovery support for Anthropic-compatible provider packages while preserving the existing OpenAI-compatible provider behavior.

## Added

### Anthropic-Compatible Provider Discovery

The V2 adapter now recognizes provider packages containing `anthropic-compatible`, including:

```json
{
  "providers": {
    "anthropic": {
      "package": "@opencode/ai/providers/anthropic-compatible",
      "settings": {
        "baseURL": "https://gateway.example.com/v1",
        "modelsDiscovery": {
          "enabled": true
        }
      }
    }
  }
}
```

The provider backend must expose an OpenAI-compatible model-list endpoint. Discovery remains opt-in in V2 and requires `modelsDiscovery.enabled` to be explicitly set to `true`. The default endpoint is `/v1/models`; providers using another endpoint can configure `modelsDiscovery.endpoint`.

This support is intended for Anthropic-compatible adapters backed by services that expose an OpenAI-compatible model catalog. It does not change Anthropic request handling or make a standard Anthropic API endpoint discoverable through the OpenAI model-list protocol.

## Changed

### V2 Provider Documentation

The provider and configuration guides now document both compatible provider package families:

- packages containing `openai-compatible`;
- packages containing `anthropic-compatible`.

Model filtering continues to use `models.includeBy` and `models.excludeBy`. The legacy `models.include` field is not supported.

### Development Dependencies

The release branch also includes routine dependency updates for the test tooling, Node.js type definitions, the OpenCode plugin SDK, and the plugin security scanner action.

## Compatibility

- Existing OpenCode v1 configurations remain supported.
- Existing OpenAI-compatible V2 providers retain their previous discovery behavior.
- OpenCode v2 discovery remains beta and requires a V2 host with the V2 plugin API.
